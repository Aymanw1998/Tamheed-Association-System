# מסמך חירום: מערכת תמהיד

איפה כל דבר נמצא, ומה עושים כשמשהו נופל. נכתב ב-2026-11-16 לפי החלטת הבעלים.

> **המאגר ציבורי.** במסמך הזה אין ולא יהיו סיסמאות, מפתחות, כתובות IP או פרטי התקשרות. הם נמצאים ב**דף הסודות** (למטה), שנשמר מחוץ למאגר.

## דף הסודות (מחוץ למאגר)

דף אחד, מודפס או בקובץ מוצפן, אצל הבעלים ועוד אדם אחד בעמותה. בכל שינוי באחד הפריטים מעדכנים אותו.

| פריט | למה צריך אותו |
| --- | --- |
| כניסה לחשבון Kamatera | השרת עצמו: הפעלה מחדש, מסוף, חיוב |
| כניסת SSH לשרת (משתמש ומפתח או סיסמה) | כל פעולה בשרת |
| עותק של `server/config/.env` | בלעדיו אי אפשר להקים את המערכת מחדש |
| `PASSWORD_ENC_KEY_HEX` (בתוך ה-.env) | בלעדיו אף אחד לא יכול להיכנס, והסיסמאות אבודות |
| `BACKUP_ENC_KEY_HEX` (בתוך ה-.env) | בלעדיו אי אפשר לפתוח את הגיבויים שב-Google Drive |
| חשבון Google של העמותה | ה-Drive: קבצים, תמונות, מסמכי רכב וגיבויים |
| הכניסה לרשם הדומיין | הכתובות של המערכת, אתר ה-IT ואתר הספורט |
| חשבון GitHub של המאגר | הקוד |
| מספר הזהות והסיסמה של חשבון המערכת | כניסה כשכל השאר נעול |
| מי לפנות אליו: המפתח, איש ה-IT, אחראי בעמותה | שמות וטלפונים |

## מה עושים כש...

### האתר לא נפתח, או מופיע 502

1. נכנסים לשרת ב-SSH.
2. `pm2 status`. אם `tamheed` לא `online`:
   ```bash
   pm2 logs tamheed --lines 50
   pm2 restart tamheed
   ```
3. אם MongoDB לא רץ: `sudo systemctl status mongod`, ואז `sudo systemctl restart mongod`.
4. אם הדיסק מלא (`df -h /`): לפי `deploy/DEPLOY.md`, סעיף «מקום בדיסק».
5. אם השרת עצמו לא עונה ל-SSH: מפעילים אותו מחדש מהאתר של Kamatera.

### אף אחד לא מצליח להיכנס

- אחרי עדכון או העברה: `PASSWORD_ENC_KEY_HEX` בקובץ ההגדרות לא זהה לערך שבדף הסודות. מחזירים את הערך הנכון ומריצים `pm2 restart tamheed --update-env`.
- משתמש אחד נחסם (5 ניסיונות שגויים): באתר ה-IT, בדף המשתמש, «رفع الحظر».
- חשבון המערכת אבד: `cd /var/www/tamheed/server && npm run system:recover` (שולח סיסמה זמנית למייל שב-`SYSTEM_ADMIN_EMAIL`).

### התראה אדומה באתר ה-IT על הגיבוי או הדיסק

- «فشل» ליד הגיבוי: `tail -50 /var/log/tamheed-backup.log`.
- «فشل» ליד העותק ב-Drive: חשבון Drive לא מחובר («التخزين» באתר ה-IT), או ש-`BACKUP_ENC_KEY_HEX` חסר.
- «لم يعمل في الوقت المتوقع»: ה-cron לא רץ. בודקים `sudo crontab -l`.
- דיסק: לפי `deploy/DEPLOY.md`, סעיף «מקום בדיסק».

### עדכון שבר משהו

לא מריצים עדכון נוסף. פונים למפתח עם שעת העדכון ומה לא עובד. חזרה לגרסה הקודמת נעשית רק על ידי מי שמכיר את הקוד.

### השרת אבד לגמרי

1. שרת חדש לפי `deploy/DEPLOY.md`, סעיפים 1 עד 6, עם קובץ ההגדרות מדף הסודות.
2. מורידים מ-Drive את הגיבוי האחרון מהתיקייה «النسخ الاحتياطية».
3. מפענחים ומשחזרים לפי `deploy/DEPLOY.md`, סעיף «גיבוי לילי» ← «שחזור מעותק שב-Drive».
4. בודקים כניסה, רשימת תלמידים ותוכנית שבועית.
5. מעדכנים את הדומיינים לכתובת של השרת החדש.

### נמחק משהו בטעות

- תלמיד, רכב או איש צוות: «سلة المحذوفات» בתפריט, 30 יום. אחרי זה רק מגיבוי.
- הודעה בלוח המודעות: «المحذوفات» בלוח עצמו.
- כל דבר אחר: מגיבוי, על ידי המפתח. שחזור מגיבוי מחליף את כל המסד, ולכן משחזרים קודם למסד נפרד ומעתיקים רק את מה שחסר.

## בדיקה חודשית

פעם בחודש, כ-10 דקות:

1. אתר ה-IT, «حالة الخادم»: הכול «سليم».
2. «ملخص الأخطاء»: אין שגיאה שחוזרת הרבה.
3. Google Drive, «النسخ الاحتياطية»: יש עותק מהלילה האחרון.
4. דף הסודות עדיין נכון.
5. בדיקת ספריות, כשהבעלים מבקש. בשרת:
   ```bash
   cd /var/www/tamheed/server && npm audit --omit=dev
   ```
   מה שמסומן `high` או `critical` עובר למפתח. לא מריצים `npm audit fix` בשרת.
